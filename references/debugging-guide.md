# 排障指南

## 第一小时

1. 完整读错误：堆栈第一处业务代码、错误码、请求 ID。
2. 确认环境：版本、配置、数据、平台是否与正常环境一致。
3. 找最近改动：`git log --oneline -20`、`git diff <last-good>..HEAD`。
4. 查已知问题（可选）：用完整错误、错误码、依赖版本查官方 issue、变更日志与社区讨论；外部结论只作线索，必须本地复现验证。搜索失败时记录未验证项与盲区。
5. 最小复现：能不能用一条命令稳定触发。

## 二分定位

- 代码：注释掉一半逻辑 / `git bisect` 找引入提交。
- 输入：从完整输入逐步删减，保留最小触发集。
- 环境：换机器、换配置、换数据，确认变量。

## 常见根因

- 空值或默认值在特定路径未生效。
- 时区/编码/精度差异。
- 并发下的共享状态或顺序依赖。
- 缓存未失效或缓存键冲突。
- 配置在目标环境缺失，回退到错误默认值。
- 依赖版本漂移。

## 修复原则

- 修根因，不吞异常。
- 不加无意义重试与 sleep。
- 修复必须配回归测试。
- 修复范围最小，不顺手重构。

## 收尾

- 删除临时日志、调试代码、临时脚本。
- 记录现象、根因、修复、验证。
- 根因未确认时明确标注，并列出剩余风险。
